# Math, units and Document2 integration verification

[← Development index](README.md) · [Equation architecture](../architecture/equations.md)

This is the **maintenance/test procedure**, not a second hardcoded LaTeX whitelist. The authoritative AI-facing syntax is generated by [`math_authoring_capabilities.py`](../../backend/app/services/math_authoring_capabilities.py) and exposed by `GET /api/v1/math/authoring-capabilities` (verify exact route from [router](../../backend/app/routers/math_authoring.py)); normal MCP clients should discover it through `get_math_authoring_capabilities`.

## Standard debugging order

1. Discover the current canonical interoperable LaTeX contract with the **normal MCP**; do not infer support from vanilla MathJax, XeLaTeX or Burhan's permissive generic parser.
2. Retrieve the current draft outline/blocks and real IDs; use a new `command_id` with the observed `base_revision`.
3. Apply a supported inline-math command through normal MCP. FastAPI invokes Burhan to make a strict Arabic `MathObject`, then BuTeX to apply and normalize the Document2 operation.
4. Read the new authoritative revision. Check equation mappings and unit conventions by the normal MCP read tools or relevant API.
5. Use [Developer MCP](developer-mcp.md) diagnostics to inspect individual conversion/worker stages, trace IDs and named fixture suites if unexpected.
6. Use **[Playwright MCP](playwright-mcp.md)** to open the draft in the real development editor; inspect Arabic glyphs, RTL operators, MathJax rendering, selection/edit/reopen and console/network output.
7. When relevant, compile an explicit preview for the exact revision and check the PDF separately; compilation is not automatic on every edit.
8. Repeat a normal MCP readback/reconstruction path when supporting bidirectional English representation is part of the tested feature.

## Unit conventions

The authoritative catalogue/grammar originates in **Burhan** and is exposed through Al-Bayan. Discover `get_unit_registry` and the current unit-conventions tools through normal MCP rather than baking old unit lists into prose. Validate article-scoped mappings and compare them under concurrent changes; use a disposable development draft.

## Result reporting

Separate **source contract**, **live service response**, **stored revision**, **browser/MathJax observation** and **compiled PDF**. A success at one layer does not prove the next. A development-only diagnostics pass cannot substitute for an end-user MCP check. For browser tests, confirm <https://dev.albayan-journal.org> uses development API origins.

### When changing syntax support

Review the pinned upstream Burhan/BuTeX source snapshot in the capabilities service, update the conservative whitelist and cases there, run relevant backend tests and targeted development fixtures, then verify normal MCP + browser/compile round trips. This document intentionally contains no static command whitelist or dated deployment-pass claims.
