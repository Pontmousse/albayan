# تدقيق الأرقام الظاهرة في الواجهة

تاريخ التدقيق: ١ أيلول ٢٠٢٦م  
النطاق: الشيفرة الموجودة تحت `frontend/src` (الصفحات، والمكوّنات، وأدوات التنسيق)

## الهدف والمصطلحات

المطلوب في مرحلة التنفيذ اللاحقة هو إضافة مفتاح في شريط التنقل يختار به
المستخدم بين:

- **الأرقام العربية المشرقية:** `٠١٢٣٤٥٦٧٨٩` (`arab`).
- **الأرقام الغربية/اللاتينية:** `0123456789` (`latn`).

هذا الاختيار يغيّر **شكل الرقم المعروض فقط**؛ فلا يغيّر قيمة البيانات، أو
التاريخ الميلادي المرسل إلى API، أو المعرّفات، أو العمليات الحسابية.

## خلاصة التدقيق

لا توجد حاليًا سياسة مركزية لشكل الأرقام:

1. التواريخ الهجرية والأوقات النسبية تمر بمكان مركزي، لكنها تثبّت اللغة
   العربية ولا تقبل تفضيل نظام الأرقام.
2. صفحة الدروس هي الموضع الوحيد الذي يحوّل الأرقام صراحةً إلى العربية
   المشرقية، ولذلك لا يمكنه عرض الأرقام الغربية الآن.
3. بقية العدّادات وأرقام الإصدارات والصفحات تُمرّر إلى React مباشرةً، فتظهر
   عادةً بأرقام غربية.
4. توجد قيمة عددية قابلة للتحرير، ورمز تحقق رقمي، وعدادات أحرف؛ وهذه تحتاج
   قرارًا صريحًا بشأن العرض مقابل الإدخال، لا مجرد تنسيق النصوص.
5. المحتوى القادم من API أو الذي يكتبه المستخدم قد يحتوي أرقامًا داخل نص
   حر. لا يمكن إحصاء هذه الأرقام من الشيفرة الساكنة، ولا ينبغي تعديلها ضمنيًا.

وبذلك تعرض الواجهة اليوم مزيجًا من النظامين.

## جرد مواضع العرض

### ١. التواريخ والأوقات

المسار المركزي هو `frontend/src/lib/format-date.ts`، ويغطي:

- التاريخ الهجري الكامل (`formatDate`).
- التاريخ والوقت الهجريين (`formatDateTime`).
- السنة الهجرية في تذييل الموقع (`formatHijriYear`).
- الوقت النسبي مثل «قبل ٥ دقائق» (`formatRelativeTime`).

يُستعمل هذا المسار في صفحات المقالات والتحرير والتحكيم والإدارة والبلاغات
والإشعارات والإعدادات، وفي بطاقة المقال والتذييل. لغة `ar-SA` ترجّح الأرقام
العربية المشرقية، لكن الخيار المطلوب ينبغي تثبيته صراحةً بامتداد Unicode
`u-nu-arab` أو `u-nu-latn` بدل الاعتماد على سلوك البيئة.

**ملاحظة:** تبقى قيمة `dateTime` في عنصر `<time>`، والقيم المرسلة إلى API،
بصيغة ISO الميلادية كما هي.

### ٢. العدّادات والإحصاءات

المواضع المؤكدة التي تعرض أرقام JavaScript مباشرةً:

| المجال | المواضع | أمثلة العرض |
| --- | --- | --- |
| لوحة المستخدم | `app/maktabi/(lawha)/page.tsx` | أعداد المسودات، وقيد المراجعة، والمنشور، ومهام المحرر والمحكّم |
| لوحة الإدارة | `app/admin/page.tsx` | بطاقات إجمالي المستخدمين والمقالات والمراجعات والمهام |
| إدارة المستخدمين | `app/admin/mustakhdimin/page.tsx` | بطاقات الأعداد الإجمالية بحسب الدور |
| المقالات الإدارية | `app/admin/maqalat/page.tsx` | عدد المراجعين والمحررين لكل مقال |
| الدعوات | `app/admin/maqalat/[id]/page.tsx` | عدد الدعوات المعلّقة |
| البلاغات | `app/balaghat/page.tsx` و`app/admin/balaghat/page.tsx` | عدد التصويتات |
| الإشعارات | `components/notifications/notification-bell.tsx` | الشارة من ١ إلى `99+` |
| المقالات المنشورة | `components/journal/published-articles-section.tsx` | عدد المقالات المنشورة |

ينبغي أن تمر كل هذه القيم عبر دالة عدد مشتركة، مع إبقاء القيم الأصلية أعدادًا
للمقارنة والحساب.

### ٣. أرقام الإصدارات والصفحات والتسلسل

- أرقام إصدارات المخطوطات ظاهرة بصيغة `v{number}` في قوائم وتفاصيل المؤلف
  والمحرر والمحكّم والإدارة تحت `app/maktabi` و`app/admin/maqalat`.
- عارض PDF في `components/dashboard/compiled-pdf-viewer.tsx` يعرض رقم الصفحة
  وإجمالي الصفحات.
- صفحة الدروس في `components/journal/lessons-folio.tsx` تعرض رقم الحلقة،
  موضع الحلقة الحالية، وإجمالي الحلقات.
- `frontend/src/lib/tutorials.ts` يحتوي محوّلًا محليًا
  `toEasternNumeral` يفرض الأرقام العربية المشرقية.
- عارض JSON التطويري في
  `components/dashboard/document-json-dev-dialog.tsx` يعرض أحجام المصفوفات
  والكائنات ومحتوى JSON الخام.

الحرف التقني `v` في تسمية الإصدار يمكن إبقاؤه، مع تنسيق الجزء العددي فقط.
أما JSON الخام في وضع التطوير فينبغي أن يبقى حرفيًا حتى يمكن نسخه وتشخيصه.

### ٤. الإدخال والحدود والعدادات

- `app/admin/maqalat/[id]/page.tsx`: حقل عددي لمهلة التحكيم (١–٣٦٥ يومًا)،
  مع رسالة تحقق تحتوي حاليًا النص الغربي `365`.
- `components/email-code-form.tsx`: رمز تحقق رقمي. يجب قبول النظامين عند
  الإدخال، ثم تطبيع القيمة إلى أرقام ASCII قبل إرسالها إلى Clerk/API.
- `components/settings/profile-form.tsx`: عداد النبذة `{bio.length}/500`.
- حقول المقالات والبلاغات والملاحظات والمفاتيح لها `maxLength`؛ الحد نفسه غير
  ظاهر غالبًا، لكنه يصبح موضع عرض إذا أضيف عداد أحرف لاحقًا.

لا يكفي تغيير شكل قيمة `<input type="number">` برمجيًا، لأن دعم المتصفحات
للأرقام العربية في هذا النوع يختلف. الأفضل أن تبقى القيمة الداخلية ASCII،
وأن تُختبر تجربة الإدخال العربية على المتصفحات المستهدفة؛ ويمكن استخدام حقل
نصي بـ`inputMode="numeric"` مع تحقق وتطبيع إذا لزم عرض المحارف العربية داخله.

### ٥. أرقام داخل نصوص حرة أو مخرجات خارجية

هذه المناطق **خارج التحويل التلقائي** افتراضيًا:

- عناوين المقالات وملخصاتها ومحتواها، وتعليقات المحكّمين، والبلاغات، وأي نص
  حر قادم من API.
- البريد الإلكتروني، وعناوين URL، وأسماء الملفات، ومفاتيح الوكلاء،
  والمعرّفات والرموز.
- مستند PDF المجمّع، وTeX المصدّر، وJSON الخام في وضع التطوير.
- الأرقام داخل SVG، وخصائص CSS/Tailwind، وسمات HTML غير المرئية، وأكواد HTTP
  وإصدارات المكتبات.

السبب هو أن الاستبدال الشامل لعقد DOM قد يفسد بيانات قابلة للنسخ، أو محتوى
المؤلف، أو عناوين وروابط. إذا تقرر لاحقًا أن يشمل الخيار نصوص المقالات، فيجب
أن يكون ذلك مطلبًا منفصلًا مع قواعد نسخ/لصق واضحة.

## التصميم المقترح للتنفيذ

1. إنشاء `NumeralProvider` عميل في التخطيط الجذري، بقيمتي `arab` و`latn`.
2. حفظ الاختيار في `localStorage` (مثل `albayan:numeral-system`) واستخدام
   `arab` افتراضيًا اتساقًا مع الواجهة العربية. يفضّل إضافة سكربت تهيئة صغير
   قبل hydration لتجنب وميض الأرقام بالنظام الافتراضي.
3. إضافة مفتاح أيقوني/مجزّأ إلى `SiteHeader` يعرض عينة `١٢٣` أو `123`، مع
   `aria-label` و`aria-pressed` ونص مساعد واضح لقارئات الشاشة. يجب إتاحته في
   شريط سطح المكتب وفي قائمة الهاتف من دون مزاحمة الإجراءات الأساسية.
4. إنشاء أدوات مركزية، مثل:
   - `formatNumber(value, system, options?)` باستخدام `Intl.NumberFormat`.
   - `formatDigits(text, system)` للنصوص التي يملكها التطبيق فقط، مثل `99+`
     و`v3`، لا لنصوص المستخدم.
   - `normalizeDigits(value)` لقبول `٠١٢٣٤٥٦٧٨٩` و`۰۱۲۳۴۵۶۷۸۹` وتحويلها إلى
     ASCII عند حدود الإدخال/API.
5. تعديل أدوات التاريخ لتنشئ المنسّقات بحسب النظام المختار، مع المحافظة على
   تقويم أم القرى: `ar-SA-u-ca-islamic-umalqura-nu-arab` أو
   `ar-SA-u-ca-islamic-umalqura-nu-latn`.
6. استبدال `toEasternNumeral` في الدروس بالأداة المركزية، ثم ترحيل مواضع
   الجرد في الأقسام السابقة.

لا يُنصح بمراقب DOM واستبدال كل `\d` بعد الرسم؛ فهذا الحل لا يغطي قيم الحقول
بصورة سليمة، ويغيّر النصوص الحرة والرموز، وقد يسبب وميضًا ومشكلات hydration.

## معايير القبول للمرحلة التالية

- يظهر المفتاح في التنقل على الهاتف وسطح المكتب، ويمكن تشغيله بلوحة المفاتيح
  وقارئ الشاشة.
- يغيّر المفتاح فورًا التواريخ والأوقات والسنوات والأعداد والعدادات وأرقام
  الإصدارات وصفحات PDF وأرقام الدروس المدرجة أعلاه.
- يستمر الاختيار بعد إعادة التحميل والتنقل، ولا ينتج عنه خطأ hydration أو
  وميض ملحوظ.
- يقبل رمز التحقق والمدخل العددي الصيغتين حيثما يسمح المتصفح، وتصل القيمة إلى
  الخادم بصيغة ASCII المتوقعة.
- لا تتغير ISO أو حمولة API أو البريد والروابط والمعرّفات والنص الحر وPDF وTeX
  وJSON الخام.
- تشمل الاختبارات الوحدية التحويل في الاتجاهين، والأعداد السالبة والعشرية،
  والفواصل والنسب، والتواريخ الهجرية، والنص المختلط مثل `v12` و`99+`.
- يشمل اختبار واجهة واحد تبديل الخيار، والتنقل إلى صفحة أخرى، ثم إعادة التحميل
  للتحقق من الاستمرار.

## حدود هذا التدقيق

هذا تدقيق ساكن للشيفرة الحالية، وليس زحفًا بصريًا لكل حالة بيانات. الشاشات
المحمية أو المعتمدة على API قد تعرض أرقامًا إضافية داخل بيانات وقت التشغيل.
لذلك ينبغي، عند التنفيذ، تشغيل حسابات مؤلف ومحرر ومحكّم ومدير ببيانات واقعية،
وفحص حالات الفراغ والخطأ والتحميل، ثم إضافة أي موضع مكتشف إلى الجرد والاختبار.
